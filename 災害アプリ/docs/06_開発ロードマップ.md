## 優先順位の考え方

**「データの質」＞「機能の数」。**
危険箇所95箇所が正確に登録され、雨量が正しく取れていれば、UIが素朴でも役に立つ。
逆に、綺麗なUIでも地点データが不正確なら害になる。**1-A（データ基盤）に最も時間を割く。**

## 最初の一歩（今週やること）

1. `prototype/` を開いて動かす（→ `prototype/README.md`）
2. 国交省 千葉国道事務所の道路冠水箇所マップPDFを入手し、95箇所の一覧を眺める
   <https://www.ktr.mlit.go.jp/chiba/chiba_index030.html>
3. 気象庁アメダスJSONを1回叩いて、千葉県の観測点と雨量が取れることを確認する
   `https://www.jma.go.jp/bosai/amedas/data/latest_time.txt`
4. 千葉市地下道冠水情報システムを見て、データ形式（API化されているか）を確認する
   <https://pub.os-alert.info/chiba/devmap>
